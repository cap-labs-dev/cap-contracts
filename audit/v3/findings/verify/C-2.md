# C-2 verification — Underwriter stale share price, ENTRY leg

**Verdict:** CONFIRMED (at the stated HIGH, with two wording corrections on the entry leg's bound).

Scope: the new claim only — that a depositor into an Underwriter after an unmarked slash overpays inside the very `deposit` that refreshes the book, and that the loss is not bounded by the underwriter's idle balance. The exit leg is unchanged from prior rounds and was only re-run, not re-verified (the prior-round verdict files are not in this checkout; only `audit/v2/tests` is).

## Code path (read end to end on HEAD a843c1d, OZ 5.7.0 installed)

`Underwriter.deposit` (:219-226) is `restricted` and calls `super.deposit`. OZ `ERC4626Upgradeable.deposit` (:205-215) computes `shares = previewDeposit(assets)` **before** `_deposit`. `previewDeposit` (:249-256) is `_convertToShares` on `totalAssets()` (:243-245) = `idle + totalDebt`; `totalDebt` is written only by `_mark` (:187-203), whose callers are `_allocate`, `deallocate`, `deallocateAsync`, `finalizeDeallocateAsync`, `_report` — every external entry to those is `restricted`. `_deposit` (OZ :273-285) then runs `_transferIn` (:282-288) → `_allocate(defaultTranche)` → `Tranche.deposit` then `_mark(tranche)` → `totalDebt` drops by L → then `_mint(shares)`. So the share count is fixed on the stale book and minted onto the fresh one, in one call. `Tranche.slash` (:71-95) moves `Tranche.totalAssets` (vault balance) and never touches the underwriter. Sequence confirmed exactly as the finding states.

## Disproof attempts, in the brief's order

1. **Precondition that cannot hold.** Needs (a) a slash on a registered, allocated tranche — reached through the real `LIQUIDATOR → market.liquidate → Tranche.slash` path in both the author's PoC and mine, no pranks on protocol contracts; (b) an admitted depositor arriving before any allocator/keeper action. Both hold. Did not land.
2. **A check elsewhere that blocks the path.** Enumerated every `_mark` caller: all `restricted` (`test_V_noPermissionlessMark` — a stranger is rejected on `report`, `allocate`, `deallocate`, `deallocateAsync`, `finalizeDeallocateAsync`). `Underwriter.maxDeposit` is OZ's `uint256.max`. The only in-path guard is `Tranche.killed` → `maxDeposit = 0` → `_allocate` reverts, and that latches only when the tranche falls below 1% of par (`test_V_killSwitchOnlyBlocksCatastrophicSlash`, price 0.01 empties the tranche and the deposit reverts). It does nothing for the 18.5% slash in the finding. Did not land.
3. **Numbers.** Re-derived independently (`test_V_entryNumbersRederived`): with A_stale = 1000e18 − 1000 (seed dust), S = 1000e18 + 1000 (Bob's quote on the seed-dusted book), L = 102 cUSD / 0.55 = 185.4545… tokens (100 repaid + 2% bonus at the crashed price), d = 100:
   - shares minted = d·(S+1)/(A+1) = 100e18 + 200 ✔ (author: 100000000000000000200)
   - value on return = d·(A − L + d)/(A + d) = 83.1404958… ✔ (author 83140495867768595042, closed form …026, mine …042)
   - loss = d·L/(A + d) = 16.8595… ✔
   - live-quote shares = d·S/(A − L) = 122.7678… ✔ (author …143102, closed form …142857)
   All within ~300 wei of tranche-share floor rounding. `mint` shape confirmed too: `mint(100 shares)` charges 100.0 assets (fair 81.45) and the shares are worth 83.14 on return (`test_V_mintOvercharges`). Without a default tranche the loss is the same 83.14, realised at `report` (author's 4th test, re-run). No error found.
4. **Severity.** Two things in the finding's entry-leg wording are over-stated and should be corrected, neither of which changes the rating:
   - "**not bounded by idle**" is true (my test has idle = 0 throughout and the loss is positive) but the loss *is* bounded: per depositor it is d·L/(A+d) < L, tending to L only as d → ∞ (whale d = 100,000 loses 183.62 against L = 185.45, `test_V_entryLossBoundedByLNotIdle`). With no default tranche, several entrants in one window lose in total (Σd)·L/(A+Σd) < L (`test_V_multipleEntrantsWithoutDefaultTrancheSumBelowL`: 52.99 for Σd = 400). So the entry leg redistributes at most the already-realised loss L from entrants to incumbents; it can never exceed L.
   - With a default tranche set (the configuration the same-tx claim relies on), the **first** deposit refreshes the book, so the entry leg is a **single-victim** event per slash: the second depositor in the same window is quoted live and loses nothing (`test_V_secondDepositorIsQuotedLive`).
   Under the third-party stance nothing changes: the entry victim is an honest depositor with no attacker at all, the beneficiaries are whoever already holds shares (curator included), and the window closes only on a KEEPER (protocol) `report` or an allocator action — neither is triggered by the slash, so the window is realistically minutes to hours, not one block. The exit leg remains the actively exploitable half (any holder or MEV bot back-running the `Slashed` event with `instantRedeem`, bounded by idle·L/A). Together: unprivileged, value moves between users, bounded by L per slash. HIGH stands for the combined finding; on its own the entry leg would be MEDIUM (honest-victim, one-shot, ≤ L).
5. **Existing tests.** `test/integration/AccountingIntegrity.t.sol`: `test_queueingADeallocationCatchesAnUnseenSlash` asserts the stale state as expected ("nothing has re-marked it yet") and only checks that `deallocateAsync` refreshes it; `testFuzz_underwriterBooksMatchWhatItCanRealise` asserts book == realisable only *after* a `deallocate` (which marks); `test_aQueuedDeallocationIsNotAWriteOff` guards the opposite direction (stale-LOW mint). No test in `test/` asserts entry or exit pricing during the window; the suite treats the staleness as accepted design (matching the `_mark` NatSpec "waits here on purpose"). Did not land.

Strongest attack: (2)+(4) — that the kill switch or the same-call re-mark bounds the harm. The kill switch only fires on a >99% wipe, and the re-mark happens *after* the quote, so it bounds the number of victims (one) but not the first victim's loss.

## Recommendation to the lead

**Keep at HIGH; re-word the entry leg.** Replace "not bounded by idle" with "not bounded by idle — bounded only by the unrecognised loss L: the first depositor loses d·L/(A_stale + d) < L, and with a default tranche the deposit's own `_mark` makes it a single-victim event (the next depositor is quoted live); without a default tranche all entrants in the window lose (Σd)·L/(A_stale+Σd) < L in total at the next report." The `mint` claim and the no-default-tranche claim both hold and can stay. The recommendation (mark before pricing on every entry and exit, overriding `deposit`/`mint`/`instantRedeem`/`instantWithdraw`/`requestRedeem`/claim paths rather than a post-hook, since OZ prices before `_deposit`/`_withdraw`) is the right fix and is cheap: `_mark` is a `convertToAssets` walk over `_registeredTranches`, no oracle. The `_mark` NatSpec's "on purpose" should be read as a gas/oracle-isolation choice whose pricing consequence the team should decide on explicitly; the existing suite never asserts the price during the window.
