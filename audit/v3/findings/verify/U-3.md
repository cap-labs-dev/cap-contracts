# U-3 verification — stcUSD "permanently" opted out of premium; `Wrapper.initialize`'s `optIn()` is the only call site

**Verdict:** CONFIRMED-AT-LOWER-SEVERITY (Medium standalone; fold into the merged U-1 as one required line of the Wrapper migration step, with a "fails silently" note). "Forever" / "never" is only true after a *bare* stcUSD upgrade, which is U-2's brick, not a new root cause.

## What I checked

**Call sites.** `grep optIn()` over `contracts/` gives exactly two callers: `Wrapper.initialize` (`contracts/cap/Wrapper.sol:46`) and `Underwriter.addTranche` (`contracts/cap/Underwriter.sol:98`, opts the Underwriter into a *Tranche*, irrelevant here). `PremiumVesting.optIn` (`contracts/utils/PremiumVesting.sol:114-123`) is keyed on `msg.sender`, `IWrapper` exposes no passthrough, and `Wrapper.initialize` cannot run on the live proxy (U-1). So HEAD as shipped has no function by which stcUSD becomes `msg.sender` of `optIn`. Confirmed.

**Accounting before opt-in.** `claimable(stcUSD)` = `pending + _owed(projected, earning) − debt` with `earning = optedIn ? balanceOf : 0` → `0 + 0 − 0 = 0` (`PremiumVesting.sol:97-101`). `Wrapper.totalAssets()` = `IERC20(cUSD).balanceOf(stcUSD) + 0`. `fund`/`fundCreditBacked` while `staked == 0`: `_accrue` only bumps `lastUpdate` (`:235-238`); `remainder` is untouched and `perShare` stays 0. Confirmed — with one nuance the author did not state: `remaining()`/`vested()` are read-ahead views that ignore supply, so `remaining()` *reports* the pot as nearly gone after a day while the storage `remainder` is intact (`vested()+remaining()==pot`, `premiumPerShare()==0`, my `test_a_forgotten…`). Anyone looking at `remaining()` to confirm "frozen" will be misled; the pot is preserved and vests to whoever opts in afterwards.

## Strongest attack and why it only partly lands

**(a) "no contract function lets stcUSD be msg.sender of optIn … forever."** Three cases, all tested offline against the v1 bytecode (`main @ 695c828`) behind fresh proxies:

1. *The migration step U-1 already requires includes it.* The out-of-tree Migrator path from U-1 (`migrateWrapper` = write `AccessManaged` slot + `optIn()`) leaves `optedIn(stcUSD)==true`, `stakedSupply()==cUSD.balanceOf(stcUSD)`, and a 1,000 cUSD `fundCreditBacked` vests 981.7 to stcUSD in 2 days, `totalAssets == balance + claimable` (`test_a_optInIsOneLineOfTheMigration…`). U-1's recommendation text already says "Wrapper: `__AccessManaged_init` + `optIn()`". U-3 is therefore the Wrapper half of U-1, not an independent defect.
2. *Authority set, opt-in forgotten:* repairable. The manager admin upgrades stcUSD to a one-off implementation that calls `optIn()` and hops back to HEAD; `optedIn` flips to true, and the premium frozen meanwhile (1,000 cUSD) then vests to stcUSD (`test_a_forgottenOptIn…`). Not permanent.
3. *Bare stcUSD upgrade (authority 0):* permanent, because no second upgrade is possible — `AccessManagedUnauthorized` (`test_a_permanentOnly…`). That is exactly U-2. Even then stcUSD holders are not trapped: `redeem` works (cUSD `claim` is live once cUSD is migrated) and pays the balance-based price including the v1 yield, and any holder can opt in personally as a cUSD holder.

So the accurate statement is: "a Wrapper migration that omits `optIn()` leaves stcUSD earning nothing until a second upgrade adds it; a bare stcUSD upgrade makes that unfixable (U-2)". The exploit path's step 1 ("upgraded with a cUSD reinitializer but no Wrapper `optIn`") is an operator omission of one line in code the operator must write anyway (HEAD has no reinitializer at all).

**(c) "100 % of every premium dollar to whoever opted in first."** True only while exactly one account is opted in, and it is the P18 rule by construction (`@dev Only opted-in balances earn`, `PremiumVesting.sol:15`): alice alone with 5,000 cUSD takes 981.7 of a 1,000 pot; once bob opts in with 9,850 the next pot splits 336.6 : 663.1, pro rata (`test_c_…`). Nothing stops any holder — including every stcUSD holder after exiting — from opting in, so the diversion is "yield forgone by stcUSD holders who stay, redistributed to opted-in cUSD holders", with no principal loss.

**Distinct contribution worth keeping:** unlike U-1/U-2, this omission fails *silently* — stcUSD deposits, redeems and `totalAssets` all keep working (`test_a_forgotten…` deposits and redeems 1 cUSD in that state) — so a fork rehearsal that only checks "does it work" will not catch it. The fork test must assert `optedIn(stcUSD)` and a non-zero `claimable(stcUSD)` after a funded premium.

## Recommendation to the lead

**Demote and merge into U-1.** Keep it as a named line-item of the Wrapper migration step ("the Wrapper reinitializer must call `IPremiumVesting(asset()).optIn()`; without it stcUSD earns nothing and the omission is silent — deposits/redeems keep working") and add to U-1's fork-test requirement: assert `cUSD.optedIn(stcUSD)`, fund a premium, warp, assert `claimable(stcUSD) > 0`. Strike "forever"/"never"/"no contract function": the true permanence condition is the bare stcUSD upgrade already rated in U-2. Re-word the impact as "stcUSD holders who stay forgo premium, which flows pro rata to whoever has opted in" (no principal loss; holders can exit at balance price and opt in themselves). Keep the `totalAssets` step as Informational with the `notify()`+`lockDuration` mitigation, and note the un-notified 6,662 cUSD is the durable part. The optional permissionless, idempotent `Wrapper.optIn()` passthrough is harmless and a reasonable belt-and-braces; mention it as optional, not as the fix. Also ask whoever owns the scratch tree to delete or fix the stale `WrapperMigrator.sol`/`V_U3_WrapperOptIn.t.sol` so the U-3 directory compiles.
