## I40 verdict

`test_I40_noRestrictedSelectorResolvesToAdminByOmission` **fails: 17 `restricted` selectors resolve to ADMIN(0) with nothing in `_configure*` naming them**:

```
[FAIL: restricted selectors resolving to ADMIN(0) without explicit wiring: 17 != 0] test_I40_noRestrictedSelectorResolvesToAdminByOmission()
  ADMIN by omission: Registry.upgradeToAndCall (UUPS)
  ADMIN by omission: Stablecoin.upgradeToAndCall (UUPS)
  ADMIN by omission: IRM.upgradeToAndCall (UUPS)
  ADMIN by omission: Oracle.upgradeToAndCall (UUPS)
  ADMIN by omission: Vault.upgradeToAndCall (UUPS)
  ADMIN by omission: Wrapper.upgradeToAndCall (UUPS)
  ADMIN by omission: BeaconFactory.upgradeToAndCall (UUPS)
  ADMIN by omission: FreshFloatingMarket(no setBorrowerRole).borrow(address,uint256)
  ADMIN by omission: FreshFloatingMarket(no setBorrowerRole).borrow(address,uint256,uint256)
  ADMIN by omission: FreshFloatingMarket(no setBorrowerRole).borrowMore
  ADMIN by omission: FreshUnderwriter(no set*Role).allocate
  ADMIN by omission: FreshUnderwriter(no set*Role).deallocate
  ADMIN by omission: FreshUnderwriter(no set*Role).deallocateAsync
  ADMIN by omission: FreshUnderwriter(no set*Role).finalizeDeallocateAsync
  ADMIN by omission: FreshUnderwriter(no set*Role).setDefaultTranche
  ADMIN by omission: FreshUnderwriter(no set*Role).deposit
  ADMIN by omission: FreshUnderwriter(no set*Role).mint
```

Three groups:
1. **`upgradeToAndCall` on all 7 UUPS proxies** (Registry, Stablecoin, IRM, Oracle, Vault, Wrapper, BeaconFactory). `_authorizeUpgrade` is `restricted`; the `restricted` modifier keys on `msg.sig == upgradeToAndCall.selector`; no `_configure*` ever calls `setTargetFunctionRole(proxy, [upgradeToAndCall], …)`, so the OZ default (ADMIN_ROLE = 0) applies. `CapRoles.ADMIN` is documented as "Upgrades and critical infrastructure", so the *effect* is the intended one, but it is reached by omission and `RoleTable.t.sol` never asserts it (see §Negative coverage). The beacons' `upgradeTo` by contrast is wired to ADMIN explicitly (`Registry.sol:410-416`).
2. **`borrow`/`borrowMore` on a market before its owner calls `setBorrowerRole`** — ADMIN can draw credit from any market whose owner has not (yet) chosen a borrower role. Note `extend` on the fresh market resolves to `ownerRole` (wired at `Registry.sol:429`) and is then re-wired to the borrower role by `setBorrowerRole` (`Registry.sol:222`); the owner wiring is dead the moment a borrower role is set.
3. **`allocate`/`deallocate`/`deallocateAsync`/`finalizeDeallocateAsync`/`setDefaultTranche`/`deposit`/`mint` on an underwriter before its curator calls `setAllocatorRole`/`setDepositorRole`** — ADMIN can deposit into and allocate from a third-party curator's vault in the window before the curator wires roles. `_configureUnderwriterRoles` (`Registry.sol:496-511`) wires only the four curator selectors and `report`.

Everything else matches `_configure*` exactly (`test_liveMatchesIntent` passes, 153 rows). Not `restricted` and therefore role-free (confirmed): `Registry.createTranche` (inline `hasRole`, ignores delay — E-6), `Tranche.slash` (`msg.sender == market`), `Stablecoin.deposit/mint/fund/coverBadDebt` and all ERC-7540 request/claim/transfer, `IRM.updateLiquidityRate`, `FloatingMarket.repay/chargePremium`, `FixedMarket.repay`, `Vault.*`, `Wrapper.*`, `PremiumVesting.optIn/optOut/claim`. `IAccessManaged.setAuthority` on every instance is ADMIN by `AccessManager.canCall`'s special case (not by wiring) — not an omission.
